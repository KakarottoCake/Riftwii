## Findings and fixes

1. `rt_hook.c` (`rt_on_sync_fs` after `rt_fs_advance(...,1)`, and
   `rt_fs_run_internal`): requests that complete on the game's thread
   free the engine without draining the async queue
   (`rt_fs_start_queued` only runs from the FILE completion). A queued
   async request is never started; later sync arrivals wait 10 s on
   `queue_count` and answer -114.
   Fix: call `rt_fs_start_queued(ctx, st)` after every thread-side
   completion (both places). Host test: during an import, the fake
   card's transfer callback injects an async request (as an IPC
   callback would) so it queues behind the internal request; after the
   import it must have been issued and its callback delivered.
   Status: done, `077a006`.

2. `rt_hook.c` `rt_fs_wait`: spins with interrupts on but never yields;
   a sync request on another game thread holding the engine cannot run
   if the waiter has equal or higher priority (SDK scheduler: no time
   slicing) -> 10 s, -114.
   Fix: make the wait tick a *synchronous* SD GETSTATUS through the
   game's sync `IOS_Ioctl` (`st->ioctl_sync`, out buffer its own
   32-byte line in the state): the SDK puts the thread to sleep until
   IOS answers, which is after the holder's SD transfer (the SD device
   serves requests in order), so the holder's thread gets the CPU.
   Fall back to spinning when `ioctl_sync` is unknown. Host: the
   stand-in `rt_host_fs_wait` stays.
   Status: done, `8e23a3a`.

3. `rt_hook.c` async rename path: `rt_fs_import` runs the whole copy
   synchronously inside the game's `IOS_IoctlAsync(Rename)` on the
   caller's thread (seconds for a multi-MB temporary).
   Fix (largest item, do last): an asynchronous import job driven from
   `rt_on_fs_complete`: the game's async `IOS_OpenAsync`/`IOS_IoctlAsync
   (GetFileStats)`/`IOS_ReadAsync`/`IOS_CloseAsync`/`IOS_IoctlAsync
   (Delete)` replay slots for the NAND side (a new tag kind, a state
   machine in the FS state), the engine's async FILE path for the card
   side (a job flag on the pend so its completion returns to the job
   rather than delivering), and the game's callback delivered at the
   end. The sync path keeps the synchronous copy. Host: `FakeIos` gains
   the async NAND stand-ins; the import test drives the job by
   completing requests one at a time.
   Status: done (this commit). As planned, with these details: the
   job's card requests queue behind a busy engine like the game's do
   (the queue entry and the pend carry a `job` flag), so the game's
   requests interleave with the import; without the async originals the
   async hook keeps the old behaviour (sync import on a thread, -102
   from a callback); the F line says P at the call and the C line comes
   at the job's end. Host: FakeIos completes NAND open/close/read/ioctl
   requests through the fake NAND; the import test drives a job from an
   IPC callback, one whose card request queues behind the game's open,
   a NAND read failing midway (cleanup), and both fallbacks.


4. `rt_hook.c` gecko reports: thread-context lines (`rt_fs_report`, DI
   `R` lines) and interrupt-context lines (`rt_fs_report_done`,
   queued-request reports, DI `M` lines) share one EXI channel without
   locking.
   Fix: print each line with interrupts off (`rt_interrupts_off` /
   `rt_interrupts_restore` around the whole line) in every report
   function. Cost: well under a millisecond per line, gecko-on runs only.
   Status: done, `5bcbf7e`.

5. `rt_hook.c` `rt_fs_clone`: files past `RT_FS_CLONE_MAX` (128) are
   silently not copied.
   Fix: `RT_FS_CLONE_MAX` 512, and every name beyond the cap counted in
   `clone_failures` and visible in the gecko `K:` count line.
   Status: done, `447b08a`.

6. `wii/boot.cpp` `prepare_savegame`: a clone runs only when the folder
   was created at this launch, so a failed or interrupted clone is never
   retried.
   Fix: a hidden marker file `riftwii.cln` inside the folder (libfat
   `FAT_setAttr` with `ATTR_HIDDEN`), created by the loader whenever a
   clone is decided (new folder, or marker still present); the runtime
   deletes it when the clone ran to its end (all names attempted), so an
   interrupted clone is retried at the next launch and a completed one
   is not. `rtfat` scans skip hidden entries unless the operation asks
   for them (`want_hidden`), so the game never sees the marker in
   lookups, listings or usage; the runtime's marker delete asks for
   hidden. With `clone="false"` the loader removes a stale marker.
   Host tests: rtfat hidden skipping and hidden delete; hook clone test
   deletes the marker at the end.
   Status: done, `5a3429c`. Also found and fixed on the way: the
   count form of ReadDir (1 in, 1 out) always answered 0 through the
   engine (a LIST of length 0); it is a COUNT now. And the clone's
   engine-side requests classify by the game's /dev/fs fd when that is
   already known (else the clone's own fd would pass through).
